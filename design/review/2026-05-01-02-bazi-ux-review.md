# 八字页面 UI/UX 审查报告

| 项 | 值 |
|---|---|
| 评估日期 | 2026-05-01 |
| 评审对象 | `/bazi` 路由(国风 guofeng + 简约 minimal 双主题) |
| 测试视口 | 1440×900(桌面) / 390×844(iPhone 14) |
| 测试用例 | 1990-06-15 10:00 男 公历 |
| 截图存档 | `.cursor/ux-review-2026-05-01/bazi-*.png` |
| 综合评价 | **B+ / 7.5 分** |

> 八字模块设计完成度高,核心命盘(四柱表 + 五行雷达 + 十神网格)信息密度合理。但与紫微类似,**首屏被表单占据**、**模态骨架屏遮挡**、**断点不一致**等通用问题存在。

---

## 一、最高优先级问题(P0)

### P0-1 · 1440 桌面端首屏依然只看到 BirthForm,排盘结果在第二屏

**证据**:`bazi-guofeng-1440.png` / `bazi-minimal-1440.png` 全页截图,前 1 屏只有标题 + BirthForm,「四柱命盘」需要滚动 1 屏才能看到。

**根因**:`BaziPage.vue:419-422` BirthForm 在 `gf-container` 的第一个位置,即使有 `chart` 数据,form 仍占视口顶端。

**修复建议**(同紫微 P0-1):
- 排盘成功后 `nextTick` + `resultBannerEl?.scrollIntoView({behavior:'smooth', block:'start'})`
- 或 ≥1024px 用「左 sticky 280px form + 右 main result」双栏布局

### P0-2 · 移动端「推演中」骨架以全屏 modal 形式遮挡所有内容

**证据**:`bazi-minimal-390.png` 早期截图(已更新),`useSkeletonReveal` 触发的 modal 居中显示「推演中」。

**问题**:此 modal 绝对居中且带遮罩,**完全锁住屏幕**,用户无法看到表单回显或滚动浏览。1.5 秒内的等待对移动用户来说是 dead time,应该展示**就地骨架**(灰色卡片占位)而不是 modal。

**修复建议**:
- A. **改为 inline skeleton**:在结果区原位渲染灰色 placeholder card(已有 CollapsibleSection 结构)
- B. 如果保留 modal,加「关闭」按钮 + 减弱遮罩 opacity 到 0.3
- C. 减短延迟到 ≤500ms(命盘计算实际只需 ~50ms,1500ms 是过度防抖)

### P0-3 · 断点 720/768 混用(同紫微 P0-3)

`themes/guofeng/components/bazi.css` 和 `themes/minimal/components/bazi.css` 同样存在,统一改 768。

## 二、高优先级问题(P1)

### P1-1 · CollapsibleSection 默认全展开,信息过载

**证据**:1440 全页可数到 7 段:命盘 → 命盘解读(纳音/十神/五行)→ 性格/事业/感情解读 → 神煞 → 大运 → 流年 → 备注。垂直滚动 5+ 屏。

**修复建议**:默认仅展开「命盘」+「五行解读」,其余 5 段折叠。

### P1-2 · 1440 桌面端内容区只用 ~50% 屏宽

**证据**:`bazi-guofeng-1440.png` 内容左右各有约 ~150px 留白,「五行雷达图」在大屏上反而显得小。

**修复建议**:`max-width: 1200px` → `width: min(94vw, 1400px)`(同紫微 P1-2)。

### P1-3 · `◈` `◎` `◆` 等 Unicode 装饰符

**证据**:`BaziPage.vue:430, 450, 486` 使用 `◈ {{ t('bazi.computeError.title') }}`,`<span aria-hidden="true">◎</span>` 等。

**修复建议**:换 `lucide-vue-next` 的 SVG 图标,或纯 CSS 装饰。

### P1-4 · 五行雷达图(ElementsRadar)在 1440 桌面下太小

**证据**:雷达图直径仅 ~120px,与右侧十神说明文字共占一行。在 minimal 主题下尤其单薄。

**修复建议**:
- 在 ≥1024px 把雷达图直径扩大到 200-260px
- 或者把雷达图与「五行能量条」(2 / 0 / 5 / 3 / 1)合并成一组「能量面板」

### P1-5 · 「能量条」颜色编码缺图例

**证据**:`bazi-guofeng-1440.png` 五行能量条颜色 = 数字 = 五行,没有 legend。

**修复建议**:在能量条下加一行小字 `木火土金水`(已有色块)对照,或鼠标 hover 提示。

## 三、中优先级问题(P2)

| ID | 问题 | 建议 |
|---|---|---|
| P2-1 | 「大运 / 小运一览」滚动条可能横溢 | 加 `overflow-x: auto` + 第一列 sticky |
| P2-2 | 流年卡片(2025 / 2026 ...)在 1440 时只用了 60% 宽 | grid auto-fill `minmax(180px, 1fr)` |
| P2-3 | 命盘四柱(年/月/日/时)字号太小,移动端难读 | 移动端字号从 14px → 16-18px |
| P2-4 | 蜘蛛图、能量条、十神网格三块视觉风格不统一 | 提取通用 chart card token |
| P2-5 | 「乙酉 旺·玉堂」这类标签密度极高,新手认知门槛高 | 加「学习模式」开关,非术语化文案 |

## 四、低优先级 / 增强(P3)

1. 流年区 `年龄`、`流年大运` 的对应关系未图示,可加横向时间线
2. 神煞解读偏专业,可加「术语小词典」浮层
3. 十神是核心概念,出现频率超过 30 次,值得单独的「我的十神画像」一段
4. 移动端「分享卡片」按钮区(底部 3 个 button)在 390 视口下可能挤压
