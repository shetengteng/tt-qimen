# tt-qimen Tauri 桌面端实现方案

> 适用范围:在不动现有 Vue3 SPA(`src/`)代码的前提下,新增一个 Tauri 2.x 桌面壳,把 tt-qimen 同时打包为 macOS / Windows 原生应用,并通过 GitHub Releases 分发(含自动更新)。
>
> 核心原则:**Web 端继续走 GitHub Pages 不变;桌面端是同一份 `dist/` 的另一种装载形态。**

## 1. 背景与目标

### 1.1 现状

| 项 | 状态 |
|---|---|
| 形态 | 纯静态 Vue 3 SPA(Vite 5),GitHub Pages 部署 |
| 路由 | `createWebHashHistory` —— hash 模式,天然兼容 `file://` 与 Tauri 的 `tauri://localhost` |
| 数据存储 | 全量 `localStorage` / `sessionStorage`(API Key、对话历史、主题、命盘) |
| AI 调用 | 浏览器直连各厂商 endpoint(`dangerouslyAllowBrowser: true`) |
| 本地计算 | `tyme4ts` / `lunisolar` / `iztro` 等纯 JS 库,无原生依赖 |
| 构建产物 | `dist/` 一份,含 gzip + br 预压缩资源 |

### 1.2 目标

1. **零侵入**:不动 `src/` 任何业务模块,SPA 既能跑浏览器也能跑桌面壳。
2. **快速交付**:macOS Universal + Windows x64 两个安装包,3 周内可发首版。
3. **可自动更新**:用户装一次后,后续版本通过 Tauri Updater 静默拉取(类似 VSCode/Notion 体验)。
4. **同源单分支**:仍只用一个 `main` 分支;新增的 Tauri 资产与 Web 端共存,互不污染。
5. **隐私语义不变**:桌面端依旧"零后端、API Key 仅本机",甚至更纯净(无 GA、无远端 CDN)。

### 1.3 非目标

- Linux 安装包(本期不做,后续可低成本补)
- 移动端(iOS/Android,Tauri 2 已支持,但与小屏 UI 适配是独立大议题)
- 把任何 Vue 端逻辑下沉到 Rust(显式排除,见 §2 决策)
- 桌面端独有功能(系统通知、托盘菜单、全局快捷键 —— 留给后续迭代)

## 2. 关键设计决策(已与产品确认)

| 决策点 | 选择 | 备选 | 理由 |
|---|---|---|---|
| **Tauri 版本** | **2.x** | 1.x | 2024 GA,API 现代化;插件生态(updater/store/keyring)在 v2 一等公民;v1 进入维护期。 |
| **Rust 侧职责** | **极简壳** | 中等(AI 代理)/ 重度(核心算法 Rust 化) | 现有 SPA 在浏览器已能跑全功能;Rust 介入越深,工作量越大、回归面越广。把 Rust 限定在"打包 + 自动更新 + 必要系统集成"。 |
| **存储策略** | **维持 localStorage** | Keyring / SQLite | 桌面端 Webview 的 localStorage 落地到本地用户目录(macOS: `~/Library/WebKit/<bundle>/`),物理上已是"本机文件"。再引入 Rust 持久化层会带来 Web / Desktop 两条数据路径的同步噩梦。 |
| **目标平台** | **macOS + Windows** | + Linux | 个人项目用户画像以 mac/win 为主;Linux 后续按需补,Tauri 跨平台成本低。 |
| **macOS 架构** | **Universal**(arm64 + x86_64) | 仅 arm64 | 单一安装包覆盖 Apple Silicon + Intel,用户无需选择。 |
| **Windows 安装器** | **NSIS** | MSI | NSIS 体积小、安装体验现代,Tauri 2 默认推荐。 |
| **AI 调用路径** | **维持前端 fetch** | Rust 反代 | CORS 在 Tauri 的 `tauri://` scheme 下天然放开;统一逻辑、零回归。 |
| **更新通道** | **GitHub Releases + Tauri Updater** | 自建 OSS / 不做 updater | Releases 免费且自带 CDN;updater 走 latest.json manifest,签名校验由 Tauri 内置。 |
| **路由模式** | **保持 hash** | 切 history | Tauri 内嵌 Webview 使用 `tauri://localhost`,history 模式刷新会失败;hash 完美兼容。 |
| **窗口策略** | **单窗口 + 系统菜单** | 多窗口 | MVP 不引入复杂窗口管理;`tauri-plugin-window-state` 记忆尺寸/位置即可。 |

## 3. 总体架构

```text
┌─────────────────────────────────────────────────────────────────┐
│                         tt-qimen v0.1.0                          │
│                                                                  │
│   ┌──────────────────────┐         ┌──────────────────────────┐  │
│   │   Web 形态 (Browser) │         │   Desktop 形态 (Tauri)   │  │
│   │   GitHub Pages       │         │   .dmg / .exe            │  │
│   │   tt-qimen.github.io │         │   github-releases        │  │
│   └──────────┬───────────┘         └──────────┬───────────────┘  │
│              │                                │                  │
│              │ 同一份 dist/                   │ 同一份 dist/      │
│              ▼                                ▼                  │
│   ┌─────────────────────────────────────────────────────────┐   │
│   │              Vue 3 SPA (src/, 业务零改动)               │   │
│   │   • 8 大占卜模块  • AI 侧栏  • 双主题  • 三语 i18n        │   │
│   └─────────────────────────────────────────────────────────┘   │
│              │                                │                  │
│              ▼                                ▼                  │
│   ┌──────────────────────┐         ┌──────────────────────────┐  │
│   │   Browser Runtime    │         │   Tauri Runtime (Rust)   │  │
│   │   • localStorage     │         │   • WebView (Wry)        │  │
│   │   • fetch → 各厂商   │         │   • IPC (extremely thin) │  │
│   │   • GA4 (可选)       │         │   • Updater Plugin       │  │
│   │                      │         │   • Window-state Plugin  │  │
│   └──────────────────────┘         └──────────────────────────┘  │
└─────────────────────────────────────────────────────────────────┘
```

**关键事实**:
- Vue 端**不感知**自己跑在浏览器还是 Tauri,所有判断通过 `import.meta.env` + 一个 `isDesktop` 探测(可选)。
- Rust 侧只挂 1~2 个 plugin,不实现任何业务 command。
- 同一份 `dist/` 既能上传到 GitHub Pages,又能被 Tauri 打包进 `.dmg/.exe`。

## 5. 前端最小改动清单

> **总原则:Vue 业务代码 0 行改动。** 以下改动仅集中在配置文件、main.ts 一处探测、README。

### 5.1 `vite.config.ts` 改动

新增 Tauri 模式探测,**仅在 `tauri` 构建期**改一个 base path:

```typescript
const isTauri = process.env.TAURI_ENV_PLATFORM !== undefined

export default defineConfig({
  // 浏览器 Pages 模式: '/tt-qimen/'
  // 浏览器本地: '/'
  // Tauri 模式: './'  (相对路径,适配 tauri:// scheme)
  base: isTauri ? './' : (isGithubPages ? '/tt-qimen/' : '/'),
  // ...其他保持不变
  build: {
    // Tauri webview 不需要 modulepreload polyfill (现代 Chromium)
    target: isTauri ? 'es2022' : 'es2020',
    // ...
  },
  // ...
  server: {
    port: 5180,
    strictPort: true,
    // Tauri dev 需要监听 0.0.0.0 才能让 webview 连接
    host: isTauri ? '0.0.0.0' : 'localhost',
    hmr: isTauri ? { protocol: 'ws', host: 'localhost', port: 5181 } : undefined,
  },
})
```

**判定原理**:`@tauri-apps/cli` 启动 dev/build 时会注入 `TAURI_ENV_PLATFORM` 环境变量,不会泄漏到浏览器构建。

### 5.2 `src/main.ts` 改动(可选,建议)

新增**1 处** runtime 探测,供后续可能需要的"桌面端独有 UI"使用:

```typescript
// src/lib/runtime.ts (⊕ 新增,与现有 lib/ 平级)
export const isTauri = '__TAURI_INTERNALS__' in window
```

> 之所以选这个判定:Tauri 2 在 webview 注入 `window.__TAURI_INTERNALS__`,即使关掉 isolation 也存在。比 UA 检测稳。

`main.ts` 暂不改;`isTauri` 只在未来真要做差异化(如:桌面端不加载 GA4、显示菜单栏)时才被引用。

### 5.3 `package.json` 改动

新增 4 个 script + 1 个 dev dep,**不动任何现有依赖**:

```jsonc
{
  "scripts": {
    // 现有保持不变
    "dev": "vite",
    "build": "vue-tsc --noEmit && vite build",

    // ⊕ 新增
    "tauri": "tauri",
    "tauri:dev": "tauri dev",
    "tauri:build": "tauri build",
    "tauri:icons": "tsx scripts/tauri/gen-icons.ts"
  },
  "devDependencies": {
    "@tauri-apps/cli": "^2.0.0"  // ⊕ 仅这一个
  }
}
```

> 注意:**不**装 `@tauri-apps/api`(因为前端不调任何 invoke);如未来需要再装。

### 5.4 `README.md` 补充

在现有"启动"章节后,新增**桌面端**小节:


#### 6.2 配置要点解析

| 配置 | 价值 |
|---|---|
| `version: "../package.json"` | 单一版本号事实来源,**避免** `package.json` 与 `tauri.conf.json` 双写不一致。 |
| `identifier: "us.tt.qimen"` | 反向域名;macOS Keychain / Windows 注册表均按此分桶,**一旦发布不可改**。 |
| `security.csp` | 显式列出所有 AI Provider host,既是安全防线也是文档;新增 Provider 时同步此处。 |
| `bundle.targets` | `app`(macOS .app)+ `dmg`(分发)+ `nsis`(Windows 安装器);不要 `msi`(体积大、UX 老)。 |
| `bundle.icon` | 顺序敏感:Tauri 按数组顺序匹配尺寸;`.icns` 与 `.ico` 必须在末尾。 |
| `plugins.updater.endpoints` | **Latest 路径**而非具体版本路径,这样每次发布只需替换 `latest.json` 不改配置。 |
| `plugins.updater.pubkey` | **公钥进库**,私钥在 GitHub Secrets;签名校验由 Tauri 运行时完成。 |

### 7.1 `src-tauri/Cargo.toml`

```toml

authors = ["shetengteng"]
edition = "2021"

[lib]

crate-type = ["staticlib", "cdylib", "rlib"]

[build-dependencies]

[dependencies]
```

## 10. 自动更新(Updater)设计

### 10.1 流程

```text
应用启动 (Vue mounted)
        │
        ▼
检查更新 (5s 后台,不阻塞 UI)
        │
        ▼
拉取 latest.json
        │
        ▼
对比版本 → 有更新?
        │
        ▼ 是
公钥验签 latest.json (Tauri 内置)
        │
        ▼ 通过
弹原生对话框 "发现新版本,是否更新?"
        │
        ▼ 用户同意
下载平台对应 payload (.tar.gz / .nsis.zip)
        │
        ▼
公钥验签 payload
        │
        ▼ 通过
应用本地补丁 → 重启 app
```

### 10.2 关键决策

| 项 | 选择 | 理由 |
|---|---|---|
| 检查时机 | 启动后 5s | 不阻塞首屏;首屏排盘体验优先。 |
| 检查频率 | 每次启动 1 次 | 桌面端用户通常一天开 1~2 次,够频繁。 |
| 弹窗策略 | 用户主动同意 | 不静默安装,避免"用户在算盘中途被打断"的体验问题。 |
| 失败兜底 | 静默失败 + console.warn | 不阻断使用;下次启动重试。 |
| 回滚 | 不内置 | 让用户去 Releases 下载旧版手动安装(MVP)。 |

### 10.3 前端集成代码(可选,后续加)

> 当前 §5 已声明"main.ts 暂不改";如要做自定义 UI,后续:

```typescript

export async function checkForUpdates() {
  if (!isTauri) return
  const { check } = await import('@tauri-apps/plugin-updater')
  try {
    const update = await check()
    if (update?.available) {
      // 用项目现有 Modal 体系弹窗,而非 Tauri 默认 dialog
      // ...
    }
  } catch (err) {
    console.warn('[updater] check failed', err)
  }
}
```

> 这要求 `tauri.conf.json` 把 `plugins.updater.dialog` 改为 `false`,并安装 `@tauri-apps/plugin-updater`。**MVP 阶段保持原生 dialog**,留后续迭代。

## 11. 签名与公证(macOS/Windows)

### 11.1 macOS

| 步骤 | 必要性 | 成本 |
|---|---|---|
| Apple Developer Program | ★ 必须(否则 Gatekeeper 拦截) | $99/年 |
| Developer ID Application 证书 | ★ 必须 | 含在会员中 |
| 公证 (notarytool) | ★ 必须(macOS 11+ 强制) | 免费,流水线自动 |
| App Store 上架 | 不做 | - |

`tauri-action` 集成签名 + 公证全流程,只需在 GitHub Secrets 配:
- `APPLE_CERTIFICATE`(p12 base64)
- `APPLE_CERTIFICATE_PASSWORD`
- `APPLE_SIGNING_IDENTITY`(`Developer ID Application: Your Name (TEAMID)`)
- `APPLE_ID` / `APPLE_PASSWORD`(app-specific password)/ `APPLE_TEAM_ID`

### 11.2 Windows

| 步骤 | 必要性 | 成本 |
|---|---|---|
| 代码签名证书(OV/EV) | ☆ 推荐(避免 SmartScreen 警告) | $80~$400/年 |
| 不签名 | ☆ 可行(用户首次运行点"仍然运行") | $0 |

**MVP 决策:Windows 暂不签名**,首版接受 SmartScreen 警告;后续若用户反馈强烈再补 EV 证书。

### 11.3 Tauri Updater 签名(独立于平台签名)

```bash
# 本地一次性生成
npm run tauri signer generate -- -w ~/.tauri/tt-qimen.key
# 输出公钥(base64) → 填入 tauri.conf.json plugins.updater.pubkey
# 私钥 + 密码 → 加密放入 GitHub Secrets (TAURI_SIGNING_PRIVATE_KEY)
```

> **私钥不进 git**,密钥丢失=无法发新版本(用户需手动重装)。建议同步备份到 1Password 等密码管理器。
